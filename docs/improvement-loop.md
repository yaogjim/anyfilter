# 用标注改进 AnyFilter 的流程

## 数据分三层，不混用

| 层级 | 来源 | 用途 | 不能用来 |
| --- | --- | --- | --- |
| 金标 | 没看过任何模型意见的盲标 | 评估、验收、回归 | — |
| 银标 | 在时间线复核模式里标的（看着模型判断） | 找问题、调阈值、提候选 | 单独当标准答案 |
| 铜标 | 三个模型的交叉验证 | 排序、预填建议 | 训练或评估过滤器本身 |

铜标只在开发侧生成，不进发布版。三模型一致率的实测在 `docs/rule-tuning-2026-09.md`：一致说“保留”的 85% 与人一致，一致说“隐藏”的 70%，分歧的一半对一半，所以只能排序，不能当答案。

## 一轮迭代

1. **标注。** 在时间线里用复核工具条标“应隐藏 / 应保留 / 值得看”。侧栏“复核数据”里点“导出复核标注”得到一个 JSON。
2. **看报告。** `pnpm review:report <导出.json>`：过滤器和你的结论在哪里不一致，哪条规则漏了、哪条误伤了。
3. **写候选。** 把改动写成规则包（`rule-packs/*.json`）：改某条规则的判断文字、排除条件、示例、阈值，或新增一条自定义规则。不需要改代码。
4. **重放验证。** `pnpm rule:replay --labels <导出.json> [--labels <更多.json>] --pack <规则包.json>`：用全部标注通过 Jev 重放，算基线和候选的抓到 / 误伤 / AUC，并按门槛判定。结果是“通过 / 不通过 / 数据不足”，不会应用任何东西。
5. **你确认。** 隐藏类的改动只有你点头才上线。
6. **上线。** `pnpm rule:apply --pack <规则包.json> --yes`：把规则包盖到正在运行的扩展上（同 id 替换、新 id 追加，其他规则不动），改动前的规则备份到 `tmp/rule-backups/`。回滚：`pnpm rule:apply --rollback <备份.json> --yes`。
7. **观察。** 继续复核，再回到第 2 步。

## 门槛（`scripts/rule-replay-core.mjs`）

- 新增误伤不超过应保留总数的 3%（向上取整）。
- 净收益：新抓到 − 不再抓到 > 新增误伤。
- 改阈值或改措辞：应隐藏和应保留各至少 30 条。
- 新增规则：标注总数至少 100 条。
- 数据不够时结论是“数据不足”，不是“通过”。

## 什么时候要改代码

规则文字和阈值解决不了的才改代码：

- Jev 分不开（措辞怎么改 AUC 都上不去）：加第二级判断，模糊区间交给更强的模型。
- 需要新的信号：作者先验、帖子长度、是否纯转述、🚨 等本地规则。
- 新的内置规则、界面、数据结构。

流程：标注 → 把漏网和误伤按类型归类 → 判断配置能不能解决 → 不能就写规格 → 实现并加测试 → 用冻结的金标集回归 → 发布。

## 注意

- 自动复核放在开发侧：脚本读 `.env` 里的 key，帖子原文会发给对应服务商，所以不进发布版。
- 复核标注文件含帖子原文，只放在本机。
