# AnyFilter 远期路线图

状态：设想，未承诺，均未实现（复核模式首期、X 用户主页与 List 的适配已完成，不在本文范围；多站点设计见 `multi-site-design.md`）。首期范围见 `timeline-review-prd.md`。每项只写“想做什么”和“进入条件”，进入条件满足后再单独写需求和设计。

## 1. 模型辅助推荐金色候选

- **想做什么**：用户可编辑的“值得看”标准，模型据此对帖子打分，把候选用独立标记提示出来，由用户确认成金色。
- **进入条件**：
  - 复核模式 R1 到 R3 已上线，并积累了一批手动“值得看”的样本。
  - 你写出了可核验的“值得看”标准和例外。
  - 已确认单次请求的成本和服务商范围（沿用现有批量外发授权与预算，不在此扩大）。
- **注意**：模型分数只表示“符合该标准的程度”，不能叫质量概率，也不能用“1 减去垃圾分”来充当。

## 2. 优先阅读队列

- **想做什么**：把金色和高候选集中到一个队列里，方便回到原帖。
- **进入条件**：金色有足够数量，并且确实存在“想集中看”的使用场景。

## 3. 主动通知

- **进入条件**：优先队列稳定，并且单独定义了打扰上限和开关。默认不开。

## 4. 自动滚动

- **想做什么**：单次由你手动启动的会话，限速、限量地滚动，收集页面自然加载的内容。
- **倾向的做法**：由外部脚本通过 Chrome DevTools 驱动滚动（前面已用这种方式采集过样本），扩展只负责判定和标注，不在扩展里实现滚动状态机。
- **进入条件**：
  - 确认不违反平台条款，并有人工随时停止的手段。
  - 有时长和条数上限、去重、费用封顶。
  - 有对抽样偏差的说明。
- **不做**：自动点击、展开受保护内容、跨页面抓取。

## 5. 其他内容源与更多站点

设计见 `multi-site-design.md`，这里只记范围和进入条件。

- **已完成（阶段 1）**：X 用户主页（Posts 标签）和 List 时间线的过滤与复核。验证样本采集不覆盖它们。
- **阶段 2：通用网页的单篇文档判定。**
  - **想做什么**：用 Defuddle 读出一篇网页的标题、作者、摘要和截断后的正文，判断这页值不值得读，用页面徽标显示，复用复核的颜色约定。第一版只做手动“判断本页”。
  - **进入条件**：Defuddle 的打包体积和提取质量在至少 20 个真实站点上测过；侧栏能否拿到 `activeTab`、`permissions.request` 能否从侧栏调用已验证；你写好了文章规则的规格。
  - **权限**：可选权限，逐站授权，随时可撤销，默认关闭。不因此把 X 的站点权限扩大成全站读取。
- **阶段 3：按站点的信息流适配器**（Substack 首页与评论、Hacker News、Reddit 等）。
  - **进入条件**：阶段 2 稳定后逐个站点评估。
- **每个来源要先回答**：身份如何识别、能否外发给模型、保存多久、用户如何删除。
- **默认**：本地处理，私密内容（邮件、消息、网盘、内网）默认不外发。

## 6. 与质量评估的关系

- 复核标注与随机盲审始终分开报告。
- 金色的发现质量将来也要用独立的随机人工验收集来评估，自选的重点样本只用来改进，不用来估计总体指标。
