# 自动模式规格（阶段 2，第二版）

状态：2026-09-30 起草并实现。决定来源：你说"自动模式需要做"、"费用封顶可以高一点，10 美元"。这里写规格和取舍；实现记录在文末。

## 1. 它是什么

在你**逐站授权**过的站点上，页面加载完成后自动读一次、判断一次，把结果放到工具栏图标的徽标和侧栏里。手动的"判断本页"保持不变。

**默认关闭。** 两道闸都要你亲手打开才会发出任何请求：

1. 侧栏里的"自动判断"总开关；
2. 每个站点单独授权（浏览器自己的授权框）。没授权的站点，自动模式碰都不碰。

## 2. 先决条件：截图里那几项需不需要先做

| 项 | 要不要先做 | 理由 |
| --- | --- | --- |
| 缓存 | **要，做最小版** | 自动模式一定会同一页反复触发（刷新、切回标签页）。同一页内容不变就不该再花钱。做成会话缓存（关浏览器即清），只存内容哈希和结果，不存页面文字 |
| 页面徽标（Shadow DOM） | **不要，换成工具栏徽标** | 自动模式需要"不打开侧栏也看得见结果"。工具栏图标徽标（`action.setBadgeText`）就能做到，不需要向页面注入任何界面，也不会碰页面样式 |
| 复核标注 / 文章评估 | 不要 | 它是"评估自动结果准不准"的闭环，不是自动模式运行的前提。但因为自动模式会让误判更常被看到，它是自动模式之后最该做的一项 |
| 其他文章规则 | 不要 | 与自动模式正交 |
| `Post` / `SiteAdapter` 并入 | 不要 | 属于阶段 3 |

## 3. 授权

- 清单增加 `optional_host_permissions: ['http://*/*', 'https://*/*']`。安装时**不**索取任何新站点权限。
- 授权按**主机名**：`https://example.com/*`。在侧栏"这个站点"按钮上点一下，浏览器弹出授权框；确认后该主机记入授权列表（列表就是浏览器保存的授权，扩展没有另存一份）。子域名不算同一个站点。
- 撤销：侧栏里逐个"取消授权"，也可以在浏览器的扩展设置里撤销。撤销立即生效。
- 不授权的：`x.com`/`twitter.com`（X 有自己的按帖过滤）、模型服务商的域名、`chrome://` 等浏览器页面。
- 自动读取用 `scripting.executeScript`，靠的是该站点的授权，不靠 `activeTab`。

## 4. 什么时候会发请求

一个标签页满足**全部**条件才会被考虑：

1. 总开关开着，没有被暂停；
2. 加载完成（`status: complete`），且是**当前前台标签页**（后台标签页等它被切到前台再说，省钱也少打扰）；
3. 地址是 `http(s)`，主机已授权；
4. 这个标签页的这个地址（去掉查询串和片段）还没判过。同一个标签页里同一个地址只判一次，刷新、切走再切回来都不重判；换了地址才判新的。另一个标签页打开内容相同的页面，从会话缓存里直接得到结果，不再花钱。

然后按手动模式完全相同的顺序处理：读页面 → 代码门槛（登录页、首页、太短、拦截页，**这些不发模型**）→ 查会话缓存 → 通过预算检查 → 发一次请求 → 判定。

单页应用只改地址、没有触发"加载完成"的，第一版不处理。

## 5. 花费与打扰的上限

| 上限 | 值 | 说明 |
| --- | --- | --- |
| **费用封顶** | **10 美元**（累计） | 你定的。按 Jev 公开价 \$0.042/百万输入 token 计（输出免费），网关走同一费率。一次约 3000 token ≈ \$0.00013，所以 10 美元大约是 7 万多页；它是防失控的保险，不是日常会碰到的线 |
| 每日请求数 | 300 次/天 | 防止某个页面反复自动刷新之类的失控。本地日期，跨天清零 |
| 速率 | 单线程，两次请求至少隔 2 秒，排队最多 5 个 | 队列满了丢最旧的 |
| 连续失败 | 3 次后**暂停** | 没有密钥、被拒、断网都算。暂停后需要你在侧栏点"继续" |

- 花费先按最坏情况预扣（12,000 token ≈ \$0.0005），响应回来后按真实 token 数结算；预扣使得工作线程在请求中途被浏览器回收时只会多算，不会少算。没有密钥、被拒（401/403）、限流、断网的请求视为没有计费，退还预扣。
- 达到封顶或每日上限：自动请求全部停止，侧栏说明原因；手动"判断本页"**不受影响**（是你亲手点的）。
- "重置用量"按钮清零累计花费；封顶值本身在代码里，不做成设置项。
- 这个预算是自动模式**自己的**，与"真实评估"的预算（`evaluation-budget.ts`，每个模型 1 美元）互相独立，谁也不占谁的额度。

## 6. 结果放在哪里

- **工具栏徽标**：命中规则时显示 `MKT`（纯营销）或 `BAIT`（标题党）；没命中不显示，避免图标上总有东西。鼠标悬停的提示写"这页读起来像纯营销 · 82%（阈值 40%）"，措辞与手动一致，不写成断言。
- **侧栏**：打开"这个页面"，如果这个标签页当前地址已有自动结果，直接显示，并标明"自动判断"。也可以再点"判断本页"重新判一次。
- 不向页面注入任何东西。

## 7. 隐私与存储

- 发给模型服务商的内容与手动模式**完全一样**：标题、作者、站点、描述、小标题、正文前 2000 词、字数、是否被截断。区别只是不需要你点按钮，所以只在你授权过的站点上发生。
- 存储：
  - `chrome.storage.local`：总开关、累计花费、当天请求数、连续失败数（没有 URL，没有页面内容）。
  - `chrome.storage.session`（关浏览器即清）：每个标签页最近一次结果，含**地址**和判定；内容哈希缓存，含判定（哈希是 `sha256(地址 + 正文)`，不含页面文字）。这是第一次在会话存储里放地址，PRIVACY.md 已同步。
  - 标签页关闭时删除它的结果。
- 没有任何页面内容被写入存储。

## 8. 已知限制（第一版接受）

- 单页应用的路由切换不触发。
- 只判断前台标签页，切到后台的页面不会补判，切回来才判。
- 结果里没有"我认为对/错"的入口，所以自动结果的准确率没有反馈闭环（见第 2 节）。
- 阈值与问法来自 `article-rules.md` 5.2、5.3：纯营销较可靠，标题党召回约 35–40%（会漏掉一半以上），徽标不会出现的页面不代表没问题。
